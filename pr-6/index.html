Engineering and leadership stories

Owning a data platform end to end

Problem
Millions of sensor readings arrive every day from more than 100 plants. Every analysis and customer report depends on that data being complete, on time, and correct.
Tried
I built and run the whole path: ingestion, Airflow-scheduled Spark jobs, time-series storage in AWS Timestream, raw data in S3, and APIs in FastAPI and Django.
Worked
One owner and one set of conventions, from the first reading to the API response, so a problem gets traced in one place.
Result
More than 100 plants, millions of readings a day

From manual fault testing to automated scoring

Problem
Testing a fault-detection algorithm took days of manual work, so each change waited days for an answer.
Tried
I built a Django dashboard that runs each algorithm against the same data and scores its results the same way every time.
Worked
With one repeatable scoring method, comparisons stopped being judgment calls, and running them no longer needed a person.
Result
Days → within a day

Making e-commerce payments add up

Problem
Orders and payment records didn't always match. A customer could pay and get no order, or a retry could create a second charge or a second order.
Tried
I reconciled our orders against the payment gateway's records, which we treated as the source of truth, and found where they drifted apart.
Worked
I made payment handling idempotent, so a retried request or a repeated callback can't double-charge a customer or create a duplicate order.
Result
Orders and payments reconciled

How I lead

Habits, not titles

  • Design reviews — I ask for a short written design before work starts, and I review it for failure modes and cost before I look at style.
  • Mentoring — I pair on real work, explain why each choice was made, and give people the parts of the system that will stretch them.
  • Simple tech choices — I pick the boring tool the team already knows unless the data proves we need something else.
  • Release discipline — Small changes, tested on real data, shipped behind a way to roll back. I don't skip a step to save a day.
  • Unclear asks → specs — I turn a vague request into a one-page spec covering inputs, outputs, edge cases, and what "done" means, and I get sign-off before we build.
